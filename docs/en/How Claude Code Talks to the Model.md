# How Claude Code Talks to the Model

By intercepting Claude Code CLI requests to the Anthropic API via a mitmproxy forward proxy, we can fully observe the communication process. This analysis is based on actual captured traffic (3 questions, 8 API calls).

## 1. Setup

### Start mitmweb Forward Proxy

```bash
mitmweb --listen-port 8080
```

This automatically opens `http://127.0.0.1:8081` in your browser for visual inspection.

### Configure Claude Code to Use the Proxy

Set environment variables in the terminal before launching Claude Code:

```powershell
$env:http_proxy = "http://localhost:8080"
$env:https_proxy = "http://localhost:8080"
$env:no_proxy = ""
```

Then start Claude Code:

```powershell
claude
```

All requests from Claude Code to `api.anthropic.com` now flow through mitmproxy.

## 2. How Many API Calls Does One User Question Trigger?

Packet capture reveals that **each user input triggers multiple API requests**, not a simple one-question-one-answer exchange.

Here are the 8 requests generated by 3 questions:

| # | Type | Endpoint | Purpose | input_tokens | output_tokens |
|---|------|----------|---------|-------------|---------------|
| 1 | Topic Detection | `/messages` | Detect if "summary this project" is a new topic | 394 | 23 |
| 2 | Token Count | `/messages/count_tokens` | Pre-check MCP tool token consumption | — | — |
| 3 | **Main Conv** | `/messages` | Answer "summary this project in short" | 23,375 | 271 |
| 4 | Topic Detection | `/messages` | Detect if "who are you?" is a new topic | 396 | 23 |
| 5 | **Main Conv** | `/messages` | Answer "who are you?" | 23,711 | 64 |
| 6 | Suggestion | `/messages` | Generate ghost text suggesting user's next input | 24,156 | 9 |
| 7 | Topic Detection | `/messages` | Detect if "what tools and skills do you have?" is a new topic | 396 | 24 |
| 8 | **Main Conv** | `/messages` | Answer "what tools and skills do you have?" | 23,819 | 419 |

### Call Pattern

Typical flow for each user question:

```
User Input
  ├─ ① Topic Detection (lightweight, ~400 tokens, determines if new topic)
  ├─ ② Main Conversation (heavyweight, ~23K tokens, actually answers the question)
  └─ ③ Suggestion (optional, generates ghost text predicting user's next input)
```

Additionally, there's a **Token Count** pre-check call at session start.

## 3. HTTP Headers

```
POST /api/anthropic/v1/messages?beta=true HTTP/1.1
User-Agent: claude-cli/2.1.62 (external, cli)
anthropic-version: 2023-06-01
anthropic-beta: claude-code-20250219,interleaved-thinking-2025-05-14,prompt-caching-scope-2026-01-05
anthropic-dangerous-direct-browser-access: true
X-Stainless-Runtime: node
X-Stainless-Runtime-Version: v24.3.0
X-Stainless-Package-Version: 0.74.0
```

Key observations:

- **anthropic-beta** enables three beta features: Claude Code protocol, interleaved thinking, prompt caching
- **X-Stainless-\*** indicates the underlying Anthropic TypeScript SDK (v0.74.0) generated by Stainless
- **Node.js v24.3.0** as runtime

## 4. Request Body Structure

### 4.1 Main Conversation Request

```json
{
  "model": "claude-opus-4.6",
  "max_tokens": 32000,
  "stream": true,
  "temperature": 1,
  "system": [ ...3 text blocks... ],
  "tools": [ ...23 tool definitions... ],
  "messages": [ ...full conversation history... ],
  "metadata": { "user_id": "user_xxx_account__session_xxx" }
}
```

### 4.2 Topic Detection Request (Lightweight)

```json
{
  "model": "claude-opus-4.6",
  "max_tokens": 32000,
  "temperature": 1,
  "stream": true,
  "system": [
    { "text": "x-anthropic-billing-header: ..." },
    { "text": "You are Claude Code, Anthropic's official CLI for Claude." },
    { "text": "Analyze if this message indicates a new conversation topic..." }
  ],
  "tools": [],
  "messages": [{ "role": "user", "content": [{ "type": "text", "text": "summary this project in short" }] }],
  "output_config": {
    "format": {
      "type": "json_schema",
      "schema": {
        "type": "object",
        "properties": {
          "isNewTopic": { "type": "boolean" },
          "title": { "anyOf": [{ "type": "string" }, { "type": "null" }] }
        }
      }
    }
  }
}
```

Key characteristics: **no tools, no conversation history, JSON Schema constrained output**. Only ~400 tokens consumed.

Response example: `{"isNewTopic": true, "title": "Project Summary"}`

### 4.3 Token Count Pre-check Request

```
POST /api/anthropic/v1/messages/count_tokens?beta=true
```

```json
{
  "model": "claude-opus-4.6",
  "messages": [{ "role": "user", "content": "foo" }],
  "tools": [
    { "name": "mcp__ide__getDiagnostics", ... },
    { "name": "mcp__ide__executeCode", ... }
  ]
}
```

Sends only MCP tool definitions with a placeholder message, **no model inference triggered**, returns `{"input_tokens": 314}`. Claude Code uses this to plan context budget.

### 4.4 Suggestion (Ghost Text) Request

After the assistant responds, Claude Code may fire another request to predict the user's next input:

- Sends full conversation history + a `[SUGGESTION MODE]` prompt as the final user message
- The prompt instructs the model to predict 2-12 words of user input, no evaluative words, no questions, no Claude-like voice
- In this capture, the model output: `"how does the agentic loop work"` (only 9 output tokens)
- This is the gray ghost text suggestion seen in the CLI

## 5. System Prompt in Detail

The main conversation's `system` field is always **3 text blocks**:

| Block | Content | Cache |
|-------|---------|-------|
| Block 0 | `x-anthropic-billing-header: cc_version=2.1.62.3d5; cc_entrypoint=cli; cch=cf6d9` | None |
| Block 1 | `"You are Claude Code, Anthropic's official CLI for Claude."` | `cache_control: ephemeral` |
| Block 2 | Full instruction set (~15,000 chars): role definition, security policy, code style, tool usage rules, Memory system, environment info, etc. | `cache_control: ephemeral` |

### Block 0: Billing Identifier

Embedded in the system prompt rather than as an HTTP header. The `cch=` value changes on every call (likely a session/conversation hash), and the `cc_version` suffix also varies (`e73`, `3d5`, `3e0`, `416`).

### Block 2: Instruction Set Contents

- Role and behavior rules (security policy, code style, task execution principles)
- Tool usage guide (when to use Read/Edit/Bash/Glob/Grep, when to use Agent sub-tasks)
- Auto Memory system (persistent memory read/write rules)
- Environment info (working directory, platform, shell, model ID)
- Git status (current branch, recent commits)
- VSCode integration info (editor context, file reference format)

## 6. Tools (23 Tool Definitions)

Main conversation requests carry 23 tool definitions:

| Category | Tools | Description |
|----------|-------|-------------|
| File Operations | `Read`, `Write`, `Edit`, `NotebookEdit` | Read, write, and edit files |
| Search | `Glob`, `Grep` | Filename pattern matching, content regex search |
| Execution | `Bash` | Execute shell commands |
| Network | `WebFetch`, `WebSearch` | Fetch web pages, search the web |
| Agent | `Task`, `TaskOutput`, `TaskStop` | Launch/monitor/stop sub-agents |
| Task Management | `TaskCreate`, `TaskGet`, `TaskUpdate`, `TaskList` | Structured task tracking |
| Interaction | `AskUserQuestion`, `Skill` | Ask user questions, invoke skills |
| Planning | `EnterPlanMode`, `ExitPlanMode` | Enter/exit plan mode |
| Git | `EnterWorktree` | Create isolated git worktrees |
| MCP | `mcp__ide__getDiagnostics`, `mcp__ide__executeCode` | VS Code language diagnostics, Jupyter execution |

Each tool definition contains `name`, `description` (detailed usage instructions), and `input_schema` (JSON Schema parameter definitions).

## 7. Messages (Conversation History)

### Special Structure of the First User Message

Claude Code injects **7 content blocks** into the first user message — the actual user input is only the last one:

| Block | Tag | Content |
|-------|-----|---------|
| 0 | `<system-reminder>` | Startup hook output (`ls` of project root) |
| 1 | `<system-reminder>` | Available skills list |
| 2 | `<system-reminder>` | Full CLAUDE.md contents (~3,618 chars) |
| 3 | `<local-command-caveat>` | Local command warning |
| 4 | `<command-name>` | Triggered slash command (e.g., `/plugin`) |
| 5 | `<local-command-stdout>` | Command output (empty here) |
| 6 | (plain text) | **Actual user input**: "summary this project in short" |

> The skills list and CLAUDE.md content are placed in the user message rather than the system prompt, likely to maintain system prompt cache stability — the system prompt stays unchanged to hit the cache, while dynamic content goes into messages.

### Subsequent User Messages

Subsequent messages are much simpler, containing only the user input text with `cache_control: ephemeral`:

```json
{ "role": "user", "content": [{ "type": "text", "text": "who are you?", "cache_control": { "type": "ephemeral" } }] }
```

### Conversation History Growth

Each request sends the **full conversation history**:

- Turn 1 (Q1): 1 user message
- Turn 2 (Q2): 3 messages (user + assistant + user)
- Turn 3 (Q3): 5 messages (user + assistant + user + assistant + user)

input_tokens grow from 23,375 → 23,711 → 23,819, with the increment coming from history messages.

## 8. Streaming Response (SSE)

All requests use `stream: true`, with responses in Server-Sent Events format:

```
event: message_start
data: {"type":"message_start","message":{"id":"msg_xxx","model":"claude-opus-4.6","usage":{...}}}

event: content_block_start
data: {"type":"content_block_start","index":0,"content_block":{"type":"text"}}

event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"I'm "}}

event: content_block_delta
data: {"type":"content_block_delta","index":0,"delta":{"type":"text_delta","text":"Claude Code..."}}

event: content_block_stop
data: {"type":"content_block_stop","index":0}

event: message_delta
data: {"type":"message_delta","delta":{"stop_reason":"end_turn"},"usage":{"output_tokens":64,...}}

event: message_stop
data: {"type":"message_stop"}
```

| Event | Description |
|-------|-------------|
| `message_start` | Message begins, includes model and initial usage |
| `content_block_start` | Content block begins (text or tool_use) |
| `content_block_delta` | Incremental text fragment or tool parameter JSON fragment |
| `content_block_stop` | Content block ends |
| `message_delta` | stop_reason, final usage |
| `message_stop` | Message ends |

## 9. Prompt Caching

### Cache Markers

System prompt Blocks 1 and 2 carry `cache_control: {"type": "ephemeral"}`, as does the last user message.

### Observations from Captured Traffic

In all 8 requests, **both `cache_creation_input_tokens` and `cache_read_input_tokens` were 0**. Possible reasons:

1. The mitmproxy proxy may have affected cache key consistency
2. The `prompt-caching-scope-2026-01-05` beta may have special conditions for cache activation
3. Topic Detection calls have a different system prompt structure than main conversation calls, preventing cache reuse

Under normal direct API connection, caching should hit between multiple main conversation requests in the same session, avoiding reprocessing of ~23K tokens of system prompt.

## 10. Token Usage Analysis

| Request Type | input_tokens per call | output_tokens per call | Cost Share |
|-------------|----------------------|------------------------|------------|
| Topic Detection | ~395 | ~23 | Very low |
| Token Count | No inference | No inference | None |
| Main Conversation | ~23,000-24,000 | 64-419 | **Primary cost** |
| Suggestion | ~24,000 | ~9 | High input, low output |

**Key findings:**

- In main conversation input tokens, system prompt + tool definitions account for the vast majority (~23K); user messages and conversation history are only a few hundred tokens
- If Prompt Caching works correctly, these ~23K tokens only need to be processed once per session
- Suggestion calls have minimal output (9 tokens) but input comparable to main conversation (~24K) — non-negligible cost

## 11. Interesting Findings

1. **Billing identifier embedded in system prompt** — `x-anthropic-billing-header` is the first text block of system, not an HTTP header, so billing metadata travels with the model request
2. **cc_version suffix varies** — Topic Detection and main conversation calls within the same session use different `cc_version` suffixes (e.g., `e73` vs `3d5`), likely build hashes or call chain identifiers
3. **JSON Schema output constraint** — Topic Detection uses `output_config.format.json_schema` to force structured JSON output, yet the model still wrapped the JSON in ` ```json ``` ` markdown code fences
4. **`anthropic-dangerous-direct-browser-access: true`** — A CORS bypass header, used because Claude Code may run in a browser-accessible context
5. **First message carries heavy context injection** — Skills list, CLAUDE.md, startup hook output are all stuffed into the first user message rather than the system prompt, likely to maintain system prompt cache stability

## 13. Summary

Claude Code is not a simple "one question, one API call" system. Each user input triggers **2-3 API calls**:

1. **Topic Detection** — Lightweight call (~400 tokens), uses structured JSON Schema to determine if it's a new topic, for UI title display
2. **Main Conversation** — Heavyweight call (~23K+ tokens), carries full system prompt, 23 tool definitions, and complete conversation history
3. **Suggestion** (optional) — Generates ghost text predicting the user's next input

There's also a **Token Count pre-check** for context budget planning.

This architecture means:
- **Actual API call volume** is 2-3x what users perceive
- **Prompt Caching is critical** — each main conversation sends ~23K tokens of system prompt + tools; cache hits significantly reduce cost and latency
- **The first message handles context injection** — Skills, CLAUDE.md, hook output and other dynamic content go in user messages rather than system prompt, ensuring system prompt cache stability

Intercepting with mitmproxy makes this process fully transparent — an excellent way to understand agent architecture.
